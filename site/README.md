# Product page

The [website](https://xchrisbailey.github.io/grimoire.srcery/) is dependency-free HTML, CSS and JavaScript. Open `index.html` directly, or serve this folder with `python3 -m http.server 8000 --directory site` from the repository root.

Keep product claims and installation requirements aligned with the root README. The source's fallback download links intentionally target `/releases`, not `/releases/latest`: beta releases are prereleases. Screenshots are copied from `docs/images`; brand SVGs come from `Brand`, and Geist and its OFL license come from `Resources/Fonts`. Refresh the copies here when those sources change. No remote fonts, analytics or runtime services are required.

The preview picker progressively enhances a plain list of screenshots and captions. Keep all content readable without JavaScript, keyboard controls operable, focus visible and motion optional. Check desktop, tablet and phone widths, no-JavaScript and reduced-motion modes before publishing.

`.github/workflows/pages.yml` deploys this folder to the existing `github-pages` environment on site/workflow changes to `main`, or a manual run on `main`. GitHub Pages must remain configured to use Actions. Every Pages deploy replaces the whole site, and the installed app reads its Sparkle feed from `/appcast.xml` there, so `scripts/assemble-pages.sh` publishes this folder (minus this README) together with the `appcast.xml` from the newest release that has one, and the workflow fails if none does. Never deploy this folder alone. The release workflow deploys the same combination.

The two download links go to the latest DMG, with its version in the label, and `scripts/assemble-pages.sh` fills them in at deploy time from the feed's enclosure: it sets the href of every element marked `data-latest-dmg`, the text of `data-dmg-label` (`Download beta 4`) and the paragraph marked `data-dmg-note`. No version is written in this folder. The source keeps the GitHub Releases link and generic text, so the page still works opened directly. If you rework those elements, keep the markers: the script fails the deploy when one is missing, rather than shipping a stale link. The FAQ's Releases link is unmarked and stays the route to older builds. No native app build is involved. Paths are relative so the page works under `/grimoire.srcery/`.
